# Quiver

**Сервис выбора инструментов для AI-агентов.** Quiver стоит между агентом и MCP-серверами. На каждом шаге агента он отбирает из большого каталога подходящие инструменты и передаёт агенту только их.

## Проблема

К агентам подключают всё больше MCP-серверов, и число доступных инструментов доходит до сотен. Описания всех инструментов попадают в контекст модели на каждом шаге агента. Из-за этого:

- **растут расход токенов, стоимость и задержка**: сотни описаний — это десятки тысяч токенов на каждом шаге;
- **падает точность выбора инструмента**: среди множества похожих описаний модель путает инструменты или вызывает не тот;
- **падает качество решения задачи**: длинный контекст отвлекает модель и вытесняет полезную информацию.

Пример: 12 MCP-серверов по 20 инструментов — это 240 инструментов. Если описание инструмента занимает около 150 токенов, только описания дают 36 000 токенов в каждом запросе к модели. Quiver отбирает 6–8 нужных инструментов, и описания занимают около 1 200 токенов — в 30 раз меньше. С меньшим набором модель лучше ориентируется в инструментах и точнее решает задачу.

## Решение

Quiver — прослойка между агентом и MCP-серверами:

- индексирует описания инструментов из подключённых MCP-серверов;
- на каждом шаге находит релевантные инструменты и передаёт агенту только их;
- позволяет агенту запросить дополнительные инструменты, если нужного не оказалось;
- поддерживает задачи, где нужна цепочка вызовов нескольких инструментов;
- не зависит от поставщика модели и работает в том числе с открытыми моделями.

## Как работает сейчас

Выбор выполняет LLM. Она получает задачу и весь каталог и возвращает подходящие инструменты с причиной выбора. Ответ приходит в JSON по схеме и проверяется: имена инструментов сверяются с каталогом.

LLM подключается через OpenAI-совместимый API. Провайдер меняется через `.env`, код менять не нужно.

## API

- `POST /select-tools` — выбор инструментов для задачи;
- `GET /health` — проверка, что сервис запущен;
- `GET /docs` — Swagger с формой для запросов.

### Запуск

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env
uv run uvicorn quiver.main:app --reload
```

Переменные в `.env`:

| Переменная | Что указать |
| --- | --- |
| `LLM_API_KEY` | API-ключ провайдера |
| `LLM_BASE_URL` | адрес OpenAI-совместимого API, например `https://ai.api.cloud.yandex.net/v1` |
| `LLM_FOLDER_ID` | ID каталога Yandex Cloud |
| `LLM_MODEL` | модель, например `gpt://<folder_id>/yandexgpt/latest` |
| `CATALOG_PATH` | путь к каталогу инструментов; по умолчанию `src/quiver/data/catalog.json` |

### Пример

```bash
curl -X POST http://127.0.0.1:8000/select-tools \
  -H "Content-Type: application/json" \
  -d '{"task": "Find my Jira issues closed this week and post a summary to the #team Slack channel", "temperature": 0}'
```

```json
{
  "tools": [
    {"tool": "jira_search_issues", "reason": "To find Jira issues closed this week"},
    {"tool": "slack_post_message", "reason": "To post a summary of the found issues to the #team Slack channel"}
  ]
}
```

Коды ответа:

| Код | Когда |
| --- | --- |
| 200 | инструменты выбраны; если подходящих нет, список пустой |
| 422 | неверный запрос: пустая задача или `temperature` вне диапазона [0, 1] |
| 502 | LLM недоступна или вернула ответ, который не прошёл проверку |

### Устройство

- `models.py` — Pydantic-модели запроса и ответа. Из модели ответа строится JSON Schema для LLM.
- `llm_selector.py` — вызов LLM и проверка ответа: обрезка по `max_tokens`, пустой ответ, соответствие схеме, имена инструментов есть в каталоге.
- `main.py` — FastAPI-приложение. Клиент LLM и каталог создаются один раз при старте.
- `data/catalog.json` — каталог из 18 инструментов: Jira, Slack, GitHub, Google Drive, PostgreSQL.

## Планы

- Поиск по каталогу без LLM: эмбеддинги, гибридный поиск, реранкинг.
- Сравнение с подходом «все инструменты в контексте», с кэшированием промпта и без него. Метрики: recall@k и точность выбора, доля решённых задач, токены и стоимость на задачу, задержка. Данные: публичные бенчмарки вызова функций и MCP и синтетический набор задач.
- Веб-интерфейс: задача агенту, выбранные инструменты и причины выбора, сравнение по токенам и результату.
